# 糯叽机 → Float 备份转换器

当前部署版本：V3。

把“糯叽机”的 `.gz` 用户备份转换为 Float 可导入的原生 ZIP 备份。全部数据只在浏览器本地处理。

## 当前转换范围

- 用户身份（含头像和个人介绍）、角色卡（含头像）、私聊、基础群聊和消息
- 单一主 API 预设：地址、Key、模型、接口类型；原温度和流式设置保存在迁移元数据中
- 糯叽机论坛帖子转为 Float 小红书笔记（正文最多 3000 字符）
- 剧情聊天可选择：剧情 App、角色线下消息、两处同时导入
- 自动清理常见状态栏、思考标签、控制标签
- 长期记忆和核心事实

## 已修复的兼容问题

- 私聊会话现在使用 Float 要求的角色 ID 进行关联，角色私聊消息可以正常显示。
- 支持糯叽机备份中使用数字 `imageRef` 的角色头像和用户头像。
- 用户资料会写入 Float 的用户身份配置，包括姓名、头像、签名和个人介绍。
- 不同角色的线下记录始终完全独立；同一角色的多段剧情按时间进入该角色自己的线下时间线，并在每段开头加入带原剧情标题的明显分隔，避免上下文混乱。
- Float 剧情 App 中仍按糯叽机原始剧情分别建立独立会话，不进行合并。

如果曾经导入过旧版转换结果，建议先在 Float 中清除旧的测试数据，再使用新版重新转换、重新导入，避免旧会话残留造成重复或关联错误。

不会导入多人场景、家园、情侣空间、异世界、自定义游戏、Minimax、图片/语音 API。

## 本地运行

```bash
npm install
npm run dev
```

生产构建：

```bash
npm run build
```

## GitHub Pages 部署

最简单的发布方式是上传构建后的 4 个平铺文件：`index.html`、`main.js`、`style.css`、`worker.js`。

1. 把 4 个文件上传到 GitHub 仓库根目录。
2. 在 `Settings → Pages → Build and deployment` 中选择 `Deploy from a branch`。
3. Branch 选择 `main`，目录选择 `/(root)`，保存并等待发布。
4. 链接通常为 `https://用户名.github.io/仓库名/`。

## 安全

转换器没有后端、上传接口、统计脚本或远程存储。若选择“完整迁移”，输出 ZIP 会包含原 API Key，请妥善保管。

## 使用建议

首次请在 Float 的空白测试环境导入。验证角色、会话、消息、剧情和 API 配置无误后，再用于正式环境。
